Tôi cần thiết kế và phát triển một hệ thống quản lý báo cáo công việc với các yêu cầu sau:

## 1. YÊU CẦU TỔNG QUAN

Xây dựng hệ thống để:
- Extract dữ liệu báo cáo công việc từ file Excel
- Lưu trữ vào MongoDB (NoSQL)
- Quản lý và tổng hợp báo cáo từ nhiều nhân viên
- Hỗ trợ xây dựng dashboard phân tích

## 2. CẤU TRÚC DỮ LIỆU NGUỒN (EXCEL)

### Phần A: Thực Hiện Công Việc Tháng Hiện Tại
Kỳ báo cáo: Từ ngày 20/MM/YYYY đến 20/MM+1/YYYY

**Nhóm I: Công việc theo chức năng vị trí**
- STT (hỗ trợ phân cấp: 1, 1.1, 1.1.1, ...)
- Tên công việc
- Loại công việc
- Thời gian: Từ ngày - Đến ngày
- Mô tả yêu cầu, giải pháp để thực hiện
- Đánh giá kết quả (Đ/G KQ)

**Nhóm II: Công việc tham gia dự án**
- Cấu trúc tương tự Nhóm I
- Hỗ trợ subtask theo STT

**Nhóm III: Đánh giá chung**
- 3.1. Về công việc hằng ngày (text)
- 3.2. Thực hiện chuyên môn (text)

### Phần B: Kế Hoạch Công Việc Tháng Tiếp Theo
Kỳ kế hoạch: Từ ngày 21/MM/YYYY đến 20/MM+1/YYYY

**Nhóm I & II:** Tương tự Phần A nhưng thay "Đánh giá kết quả" bằng "Chi phí thực hiện (VNĐ)"

## 3. YÊU CẦU THIẾT KẾ DATABASE (MONGODB)

### 3.1. Schema Design
- Thiết kế collections phù hợp: employees, work_reports, projects, task_types
- Xử lý quan hệ: Nhân viên - Báo cáo - Công việc - Subtask
- Hỗ trợ phân cấp công việc (task/subtask) linh hoạt không giới hạn level
- Phân biệt rõ phần "thực hiện" và phần "kế hoạch"
- Mỗi task phải có các field: hasSubtasks (boolean), subtaskCount (number), children (array taskId)

### 3.2. Indexes
- Tạo indexes tối ưu cho query performance
- Composite indexes cho truy vấn phổ biến
- Text search index cho tìm kiếm công việc

### 3.3. Sample Documents
- Ví dụ đầy đủ cho mỗi collection
- Bao gồm cả trường hợp có subtask và không có subtask

## 4. YÊU CẦU XỬ LÝ DỮ LIỆU

### 4.1. Parse STT (Số thứ tự)
- Tự động nhận diện cấp độ: "1" (level 0), "1.1" (level 1), "1.1.1" (level 2)
- Xác định parent task dựa trên STT
- Xử lý cả trường hợp chỉ có task chính (không có subtask)
- Xử lý trường hợp mixed (một số task có subtask, một số không)

### 4.2. Parse Date
- Hỗ trợ nhiều format: dd/mm/yyyy, dd/mm/yy, yyyy-mm-dd
- Trả về datetime object hoặc None

### 4.3. Extract Report Period
- Tự động trích xuất kỳ báo cáo từ tiêu đề Excel
- Pattern: "Từ ngày dd/mm/yyyy đến hết ngày dd/mm/yyyy"

### 4.4. Identify Tasks với Subtasks
- Sau khi parse xong, tự động đánh dấu task nào có subtask
- Thêm field: hasSubtasks, subtaskCount, children[]

## 5. YÊU CẦU PYTHON IMPLEMENTATION

### 5.1. Kiến trúc
- **KHÔNG dùng Class** - Sử dụng Functional Approach
- Tách code thành các module riêng biệt:
  * config/ - Cấu hình (MongoDB URI, formats, constants)
  * utils/ - Parsers và validators
  * database/ - Connection và CRUD operations
  * extractors/ - Excel reader và task parser
  * main.py - Entry point
  * cli.py - Command line interface

### 5.2. Core Functions Cần Có

**utils/parsers.py:**
- parse_stt(stt: str) -> (level, parent_stt)
- parse_date(date_value) -> datetime
- extract_report_period(title: str) -> dict
- parse_cost(cost_str: str) -> float

**database/connection.py:**
- connect_mongodb(uri, db_name) -> (client, db)
- close_mongodb(client)
- test_connection() -> bool

**database/operations.py:**
- insert_employee(db, employee_data) -> dict
- get_employee_by_code(db, code) -> dict
- insert_work_report(db, report, auto_update) -> bool
- get_reports_by_employee(db, code, year, month) -> list
- get_reports_by_department(db, dept_code, year, month) -> list

**extractors/excel_reader.py:**
- load_excel_file(path) -> (workbook, sheet, title)
- find_section_start_rows(sheet) -> dict

**extractors/task_parser.py:**
- parse_tasks_from_dataframe(df, task_type, prefix) -> list

**main.py:**
- extract_work_report_from_excel(path, employee) -> dict
- import_single_report(db, path, employee_data) -> bool
- import_batch_reports(db, excel_files, employees) -> None

### 5.3. Features
- Batch import từ nhiều file Excel
- Validate dữ liệu trước khi insert
- Xử lý duplicate (hỏi update hay skip)
- History tracking (version, changes)
- Error handling đầy đủ

## 6. YÊU CẦU QUERY & AGGREGATION

Cung cấp các query ví dụ cho:
- Lấy báo cáo của nhân viên theo tháng
- Lấy tất cả báo cáo của phòng ban
- Tìm công việc trễ hạn
- Tổng hợp công việc theo phòng ban (completion rate)
- So sánh kế hoạch vs thực hiện
- Phân tích xu hướng theo thời gian
- Báo cáo chi phí theo dự án
- Lấy tất cả subtask của một task

## 8. RÀNG BUỘC KỸ THUẬT

- Database: MongoDB
- Python: 3.8+
- Libraries: pymongo, pandas, openpyxl, python-dotenv
- Hỗ trợ: 100-1000 nhân viên
- Performance: Query < 2s
- Lưu trữ: Tối thiểu 3 năm lịch sử

## 9. BEST PRACTICES CẦN ÁP DỤNG

- Separation of concerns (mỗi file một trách nhiệm)
- DRY (Don't Repeat Yourself)
- Error handling graceful
- Logging cho debug
- Validate input trước khi process
- Connection pooling cho MongoDB
- Reusable functions
- Clear naming conventions

## 10. EDGE CASES CẦN XỬ LÝ

- File Excel thiếu sections
- STT không theo format (vd: "a", "A1", rỗng)
- Date format không chuẩn
- Task có parentTaskId nhưng parent không tồn tại
- Duplicate report code
- Employee chưa tồn tại trong DB
- Empty tasks list
- Chi phí âm hoặc không hợp lệ
